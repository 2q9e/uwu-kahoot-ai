# Repository guidance

- Commit and push the changes requested by the user to the repository's GitHub remote once they are ready for review.
- Before committing, review the staged diff and include all intended project changes. Keep local test artifacts and unrelated files out of the commit unless requested.
- Never commit API keys, tokens, passwords, personal email addresses, private configuration, or other credentials. Check changed files for accidental secrets before pushing.
- Use neutral commit subjects that describe the code or product change. Do not describe work as copied from another project or mention another project as the source of the change in commit messages.
- Do not run tests unless the user asks.
